## 7. 로드맵 — 제외했던 기능의 복귀 지점 

### v1.5 — 비밀 반응 ✅ 구현 완료

**조건은 "N번 누르면"** 한 가지만. 결과는 숨은 그림 / 특별한 소리 / 빛 폭발 3종. 감상 화면에는 **개수만** 표시한다 — 어느 키인지도, 몇 번인지도 알려주지 않는다.

원문에 있던 "→ 스키마에 `secrets: Secret[]` 추가, `schemaVersion: 2`"는 **이미 되어 있던 일이었다.** `Secret` 타입도 `Work.secrets` 필드도 v1부터 자리를 잡고 있었고 스키마는 이미 v2다. 버전을 올릴 일도, 마이그레이션도 없었다.

대신 진짜 일은 **데이터 경로가 세 군데에서 끊겨 있던 것**이었다. 셋 다 화면에는 아무 오류도 안 내고, 남의 기기에서만 조용히 실패한다:

- `parseWork`가 `secrets: []`를 하드코딩하고 있었다 — 올라가도 읽어올 때 통째로 버려졌다
- `isAssetReferenced`가 keys만 봐서, 비밀에만 붙은 그림·소리를 `normalizeWork`가 업로드 직전에 지웠다
- 목소리를 안 올리기로 고르면 자산은 빠지는데 비밀은 남아 **열리지 않는 비밀**이 됐다

그래서 이 기능의 실패 모드는 하나로 모인다: **"비밀 N개"라고 표시되는데 아무리 눌러도 안 열리는 것.** 감상자는 없는 것을 영원히 찾는다. 파서·정규화·업로드·보안 규칙·편집 화면 다섯 군데에서 각각 막는다.

발동은 **직접 누를 때만**이다. 다시 보기(`replay`)에서 저절로 터지면 감상자가 찾을 것이 남지 않고, 녹화 중(`live`)에 화면을 덮는 연출이 끼어들면 공연을 망친다. 남는 것은 무대에서 시험하는 순간과 "직접 눌러보기"뿐이고, 둘 다 저장되지 않으므로 리플레이 결정론과도 무관하다.

편집은 편집 시트가 아니라 **무대 화면**에 붙였다. 로드맵의 제작 순서(①키캡 ②무대 ③반복 **④비밀** ⑤공연)가 그 자리이고, 비밀은 키 하나의 장식이 아니라 작품 전체에 몇 개를 숨겼는가의 문제라서다.

`SECRETS_MAX = 3`, 누름 횟수는 3~10회. 상한은 `types.ts`와 `firestore.rules` 두 곳에 같은 값으로 있다.

**v1.5에서 뺀 것:** "비밀 발견 31명" 집계. 별도 컬렉션과 Cloud Function이 필요해 재생 수 집계만큼의 작업이다.

### v1.6 — 흔적 1종 ✅ 구현 완료

흔적을 v2.5의 재질 8종과 묶어두면 재질에 발목이 잡힌다. **떼어내서 먼저 낸다.**

배선이 이미 v1에 깔려 있어 비용이 거의 없다:

- `TraceType = 'none' | 'catPaw@1' | 'star@1' | 'flower@1'`, `KeyDef.trace: {type, color}` — 스키마 자리 확보 완료(`types.ts`)
- `serialize.ts`의 `TRACES` 화이트리스트·`coerceKey`·v1→v2 마이그레이션이 이미 `trace`를 통과시킨다
- `rng.ts`의 `PURPOSE = {posX, posY, size, angle, hue, variant}` — 스탬프 흩뿌리기용으로 미리 만들어 둔 상수다
- `VisualEvent{seed, eventIndex}`가 이미 결정론적 난수 재료를 실어 나른다

즉 **schemaVersion 변경 없음, 마이그레이션 없음, 오디오 엔진 구조 변경 없음.** 실제 작업은 흔적 레이어 컴포넌트 + CSS + 편집 시트 칩 한 줄이다.

범위는 **`catPaw@1` 한 종 + 색 선택**으로 자른다. `star@1`·`flower@1`은 타입에만 남기고 UI에 노출하지 않는다.

지켜야 할 것:

1. **React state 금지.** 발자국 하나마다 setState 하면 리렌더가 오디오보다 늦게 온다 — `Keycap.tsx`가 `fire()`를 ref로 뺀 것과 같은 이유다. imperative DOM append → `animationend`에 제거.
2. **개수 상한.** 130bpm 15초 × 4키 매박자 루프면 스탬프가 100개를 넘는다. 상한을 두고 **오래된 것부터** 지운다(무작위 제거는 리플레이를 깬다).
3. **위치는 반드시 `rnd(seed, eventIndex, PURPOSE.*)`.** 작품은 영상이 아니라 리플레이다. `Math.random()`을 쓰면 감상자마다 다른 그림이 나온다.
4. **기본값 `none` 유지.** 흔적을 켜면 LED와 움직임이 가려진다. 키별 opt-in.

이걸 먼저 내는 진짜 이유는 피드다. 지금 15초 작품은 프레임이 거의 변하지 않아 **피드에서 정지 화면처럼 보인다.** 흔적이 쌓이면 화면이 시간에 따라 채워지고, 마지막 프레임이 곧 "아이가 만든 그림"이 된다. 문서 8번(피드)이 성립하려면 재질 8종보다 이게 먼저다.

### v2 — 리믹스 (출시 후 2~3개월)

작품 JSON을 복제하고 `remixOf: workId`를 심는 것뿐이라 기술 난이도는 낮습니다. **부분 가져오기**(그림만 / 소리만 / 반복 구조만)까지 넣으면 문서 5번의 리믹스 트리가 성립합니다. 다만 여기서부터 **아이 창작물의 재사용에 대한 안내와 신고 기능이 필요**해집니다.

### v2.5 — 재질 + 흔적 나머지

재질 8종은 소리·움직임·빛의 **묶음 프리셋**으로 구현하세요. 개별 옵션으로 풀면 편집기가 무너집니다.

흔적은 여기서 확장한다 — 성장형(빈 나무에 꽃이 핌), 이동형(발자국이 스스로 걸어감), 그리고 직접 그린 스탬프. 이들은 경로·상태 애니메이션이라 v1.6의 단발 스탬프와 완전히 다른 작업이다.

### v3 — 피드 (모더레이션 인력 확보 후에만)

공개 피드는 **사람이 붙기 전엔 절대 열지 마세요.** 순서는 학급 공간 → 초대 전시회 → 공개 피드입니다. 그 전에 신고 처리, 자동 필터, 보호자 관리 기능이 있어야 합니다.

### v4 — 네이티브 (React Native + Expo)

이 시점에 되살아나는 것들:

- **Core Haptics / VibrationEffect** — `haptic` 필드가 v1부터 쌓여 있으므로 데이터 마이그레이션 없이 바로 켜집니다
- 홈/잠금화면 위젯 (문서 2번의 키젯이 검증한 수요)
- mp4 내보내기
- 기기 간 근거리 공유

웹앱은 이때 버리지 말고 **감상·공유 전용 진입점**으로 남기세요. "설치 없이 눌러본다"는 문서 2번이 찾은 가장 큰 공백이고, 그건 웹에서만 됩니다. 최종 형태는 **창작은 네이티브, 감상은 웹**입니다.

# 2. 흔적 남기기를 주요 창작 도구로 만들기

이 기능은 단순한 시각 효과보다 훨씬 크게 활용할 수 있습니다.

키캡을 누를 때마다 흔적이 화면 위에 쌓이게 하면, **누르는 행위 자체가 그림 그리기**가 됩니다.

## 흔적의 종류

### 고정 흔적

누른 위치에 그대로 남습니다.

- 발자국
- 도장
- 스티커
- 색 점
- 별

### 사라지는 흔적

시간이 지나면 천천히 사라집니다.

- 빛
- 연기
- 물결
- 반짝이
- 눈

### 성장하는 흔적

누를수록 작품이 완성됩니다.

- 빈 나무에 꽃이 핌
- 밤하늘에 별이 채워짐
- 고양이가 걸어간 길이 만들어짐
- 도시의 창문에 불이 켜짐
- 공룡 발자국이 동굴까지 이어짐

### 움직이는 흔적

- 발자국이 스스로 걸어감
- 물고기가 헤엄침
- 음표가 위로 올라감
- 불꽃이 다른 키캡으로 옮겨감

아이들은 흔적의 크기, 방향, 색, 지속시간, 개수를 설정할 수 있습니다.

예를 들어:

> 고양이 키캡을 누르면 분홍색 발자국이 화면을 가로질러 걸어가고, 네 번째 발자국에서 고양이가 나타난다.

이 자체가 하나의 15초 작품이 됩니다.

예를 들어:


| 키캡  | 소리           | 반복      |
| --- | ------------ | ------- |
| 빨강  | 책상 두드리는 소리   | 매 박자    |
| 파랑  | 손뼉 소리        | 두 박자마다  |
| 노랑  | 아이의 “야!” 목소리 | 네 박자마다  |
| 초록  | 고양이 울음       | 여덟 박자마다 |


아이들은 키를 하나씩 켜면서 음악을 완성합니다.

## 연주 방식

### 직접 연주

아이의 손가락 입력만 기록합니다.

### 자동 연주

설정한 루프가 자동으로 재생됩니다.

### 함께 연주

일부 키는 자동 반복되고, 나머지는 아이가 직접 누릅니다.

이 **함께 연주 방식**이 가장 재미있습니다. 아이가 혼자서도 밴드나 오케스트라를 연주하는 느낌을 받을 수 있습니다.

# 6. 15초 작품 제작

앱의 모든 창작은 최종적으로 **15초 작품**으로 완성됩니다.

작품 형식은 단순 영상이 아니라 다음 요소가 결합됩니다.

- 키캡 디자인
- 키캡 배치
- 자동 반복 음악
- 아이의 실시간 연주
- LED 효과
- 표정 변화
- 재질 애니메이션
- 화면에 쌓이는 흔적
- 숨겨진 비밀 반응

## 제작 과정

### 1. 키캡 만들기

그림, 소리, 재질, LED, 표정을 설정합니다.

### 2. 무대 만들기

키캡을 화면에 자유롭게 배치합니다.

### 3. 반복 설정하기

각 키의 반복 간격과 시작 시점을 정합니다.

### 4. 비밀 숨기기

특정 입력에서만 나타날 반응을 설정합니다.

### 5. 15초 공연하기

녹화 버튼을 누르고 직접 연주합니다. 자동 반복 키도 함께 재생됩니다.

### 6. 작품 카드 만들기

제목과 한 줄 설명을 붙입니다.

예:

> **한밤중의 고양이 행진**  
> 고양이들이 어디로 가는지 찾아보세요. 비밀 2개.

# 7. 영상과 인터랙티브 작품을 함께 공유

완성된 작품은 두 가지 형태로 저장됩니다.

## 15초 영상

- 숏폼 피드에서 바로 재생
- 키캡 애니메이션과 음악 감상
- 외부 메신저나 소셜 미디어로 공유
- 세로형 9:16 영상

## 직접 눌러보는 작품

영상 아래에 다음 버튼을 둡니다.

> **직접 눌러보기**

감상자는 제작자가 사용한 키캡을 직접 누르고 비밀 반응을 찾을 수 있습니다.

이 구조가 중요합니다.

> 영상은 사람을 끌어들이고, 인터랙티브 작품은 오래 놀게 한다.

# 8. 15초 작품 공유 피드

피드는 일반적인 영상 SNS와 다르게 구성합니다.

각 작품은 15초 동안 자동 재생됩니다.

재생이 끝나면 세 가지 행동을 제안합니다.

### 직접 눌러보기

작품 안으로 들어가 키캡을 조작합니다.

### 비밀 찾아보기

숨겨진 반응에 도전합니다.

### 내 방식으로 바꾸기

원작자를 표시한 상태로 리믹스합니다.

댓글이나 팔로워 경쟁보다 **체험과 재창작**이 중심입니다.

## 작품 카드에 표시할 정보

- 작품 제목
- 창작자 닉네임
- 사용한 키캡 개수
- 비밀 개수
- 비밀을 찾은 사람 수
- 리믹스 수
- 작품에 사용된 소리 수
- 직접 눌러보기 버튼

좋아요는 넣더라도 크게 강조하지 않는 편이 좋습니다.

# 9. 리믹스 구조

다른 아이의 작품에서 원하는 부분만 가져올 수 있습니다.

- 키캡 모습 가져오기
- LED 패턴 가져오기
- 반복 음악 구조 가져오기
- 흔적 효과 가져오기
- 비밀 조건 가져오기
- 전체 작품을 복제해 다른 결말 만들기

원작과 리믹스 작품은 나무처럼 연결해 보여줍니다.

> 고양이 행진  
> ├ 우주 고양이 행진  
> ├ 강아지 행진  
> └ 공룡 발자국 행진

아이들은 다른 창작물을 소비하는 데서 끝나지 않고, **이어 만들고 변형하는 창작자**가 됩니다.

# 10. 어린이용 공유 안전 구조

15초 영상 플랫폼이 핵심인 만큼 처음부터 안전 구조가 필요합니다.

- 얼굴 촬영 기능 없음
- 카메라보다 작품 화면 녹화 중심
- 위치 정보 저장 금지
- 자유로운 개인 메시지 없음
- 공개 댓글 없음
- 전화번호·학교명 등 개인정보 입력 감지
- 목소리 녹음 공유 전 안내
- 목소리를 로봇·동물 음성으로 변환하는 기능 제공
- 신고와 보호자·교사 관리 기능
- 닉네임은 자동 조합 방식 제공
- 공개, 학급 공개, 링크 공개, 비공개 선택

특히 아이의 실제 목소리는 창작 재료이면서 개인정보가 될 수 있으므로, 기본값을 **음성 변형 적용** 또는 **작품 안에서만 사용**으로 두는 것이 좋습니다.

# 11. 서비스의 최종 핵심 루프

> **만든다 → 반복시킨다 → 직접 공연한다 → 15초 작품으로 공유한다 → 다른 아이가 비밀을 찾는다 → 리믹스한다**

이 루프는 기존 키캡 시뮬레이터와 완전히 다릅니다.

## 서비스의 새로운 정의

> **빛·소리·표정·재질·흔적과 비밀을 조합해 15초짜리 인터랙티브 작품을 만드는 어린이 창작 플랫폼**

## 가장 중요한 세 가지 기능

1. **키캡 기반 인터랙티브 창작기**
2. **여러 키의 자동 반복을 이용한 15초 공연 제작기**
3. **직접 눌러보고 비밀을 찾고 리믹스하는 작품 피드**

이제 키캡은 목적이 아니라, 아이들이 가장 쉽게 접근할 수 있는 **창작의 기본 단위**가 됩니다.



## 결론부터 말하면

**‘키크’는 아이디어는 매우 좋지만, 그대로 최종 브랜드로 쓰기에는 충돌 위험이 큽니다.**

이름 자체만 평가하면 매력적입니다.

- **키캡 크리에이터**의 줄임말
- 두 음절이라 초등학생도 쉽게 기억
- `키가 크다`, `창의력이 크다`, `창의력을 키운다`는 의미까지 연결 가능
- 키캡에서 시작하지만 ‘키’를 창작 블록으로 확장할 수 있음
- 발음이 짧고 장난감 같은 느낌이 있음

브랜드 스토리도 자연스럽습니다.

> **키크 — 누를수록 창의력이 큰다.**

다만 실제 사용 환경을 확인하면 문제가 있습니다.

## ‘키크’의 가장 큰 문제

한국에는 이미 **키크(KEEK)**라는 패션·라이프스타일 테크 브랜드가 운영 중이며, 무신사 입점과 오프라인 매장, 일본 진출까지 진행한 상태입니다. 검색 결과에서도 `키크`를 입력하면 이 브랜드가 강하게 노출됩니다. ([Musinsa](https://www.musinsa.com/brand/keek?utm_source=chatgpt.com "키크(KEEK) | 무신사 추천 브랜드"))

더 큰 문제는 영어 표기 `KEEK`입니다. **Keek는 과거 대규모 사용자를 확보했던 숏폼 영상 소셜 서비스이고 2023년 다시 출시된 브랜드**입니다. 사용자의 서비스도 15초 창작 영상 공유 플랫폼이므로, 단순히 이름만 같은 것이 아니라 서비스 영역까지 가까워집니다. ([Wikipedia](https://en.wikipedia.org/wiki/Keek?utm_source=chatgpt.com "Keek"))

따라서 다음 표기는 추천하지 않습니다.

> **키크 / KEEK**

한국어 검색에서는 패션 브랜드와 충돌하고, 글로벌에서는 영상 SNS와 충돌합니다.

# 1. 키크를 유지한다면 영어는 `KEYK`

키크라는 한국어 이름을 꼭 살리고 싶다면 공식 영문은 다음이 가장 낫습니다.

## 추천 표기

> **키크**  
> **KEYK**

`KEYK`는 첫 부분에 `KEY`가 명확히 보여 키캡·키보드·누르는 창작물과 연결됩니다. `KEEK`와 철자가 달라 기존 영상 서비스와도 어느 정도 구별됩니다.

### 사용 방식

**로고**

> KEYK

**한국 앱 이름**

> 키크 KEYK

**앱스토어 전체 이름**

> 키크 KEYK – 15초 인터랙티브 창작

**영어 앱 이름**

> KEYK – Interactive Creation Studio

**서비스 설명**

> Create sounds, lights, loops, secrets, and 15-second interactive works.

`KEYK`는 영어 단어가 아니기 때문에 처음 보는 해외 사용자가 발음을 바로 알기 어렵습니다. `Key-K`, `Keek`, 심지어 `Cake`처럼 읽을 가능성도 있습니다. 실제로 `keyk`는 일부 언어에서 cake를 뜻하는 표기로 사용됩니다. ([Wiktionary](https://en.wiktionary.org/wiki/keyk?utm_source=chatgpt.com "keyk - Wiktionary, the free dictionary"))

그래서 초기 화면이나 소개 영상에서 다음처럼 발음을 알려주는 것이 좋습니다.

> **KEYK, pronounced “keek.”**

하지만 초등학생 대상 글로벌 서비스에서는 발음 설명이 필요한 이름 자체가 작은 약점입니다.

# 2. ‘키캡 크리에이터’라는 뜻은 너무 좁아질 수 있다

현재 서비스에는 이미 다음 요소가 들어갔습니다.

- 키캡 디자인
- 직접 녹음한 소리
- LED 패턴
- 표정과 재질 변화
- 발자국과 흔적
- 숨겨진 반응
- 여러 키를 반복 재생하는 음악 루프
- 15초 공연
- 작품 공유와 리믹스

이제 아이들이 만드는 것은 사실상 **키캡**이 아니라 **15초 인터랙티브 작품**입니다.

따라서 ‘키캡 크리에이터’는 시작점을 설명하기에는 좋지만 장기적인 서비스 정의로는 좁습니다. `KEYK`의 의미도 나중에는 다음처럼 넓히는 편이 좋습니다.

> **KEYK = Create with Keys**

또는:

> **KEYK = Keys for Creativity**

한국에서는 여전히 “키캡 크리에이터에서 시작된 키크”라고 설명할 수 있습니다.

# 3. 키크를 보완한 이름

## 1위: 키크 플레이 — `KEYK PLAY`

제가 가장 현실적으로 추천하는 방식입니다.

> **키크 플레이**  
> **KEYK PLAY**

### 장점

- 기존에 마음에 든 `키크`를 유지
- 패션 브랜드 ‘키크’와 완전히 같지는 않음
- 만들기와 감상뿐 아니라 연주·비밀 찾기·리믹스까지 표현
- 초등학생에게 교육 도구처럼 무겁게 느껴지지 않음
- 키캡을 넘어 다양한 반응형 장난감으로 확장 가능

### 단점

- 여전히 한국어로는 기존 키크 브랜드와 연결될 수 있음
- `Play`가 창작보다 놀이를 더 강조함

### 추천 표기

> **KEYK PLAY**  
> 누르면 살아나는 15초 창작 놀이터

영문 태그라인:

> **Create it. Tap it. Bring it to life.**

# 4. 완전히 새로운 이름 후보

# 5. 피하는 것이 좋은 후보

## `KEYPOP`

키캡을 누르고 수집하는 동명의 앱이 이미 Google Play에 있으며, 키 입력 사운드를 제공하는 다른 `KeyPop` 앱도 존재합니다. 직접 경쟁 영역이라 피하는 것이 좋습니다. ([App Store](https://apps.apple.com/us/app/keypop/id6478332106?mt=12&utm_source=chatgpt.com "KeyPop - App Store - Apple"))

## `KEYCRAFT`

타이핑 분석 앱, MIDI 편집기, 장난감 기업 등에서 이미 널리 사용됩니다. 특히 “키로 창작한다”는 의미는 좋지만 고유성이 약합니다. ([App Store](https://apps.apple.com/ar/app/keycraft/id6744457788?l=en-GB&platform=vision&utm_source=chatgpt.com "KeyCraft - App Store - Apple"))

## `KEYLOOP`

음악 루프와 잘 맞지만, 이미 여러 국가에서 사업하는 대형 자동차 소프트웨어 기업의 이름입니다. ([Keyloop](https://keyloop.com/?utm_source=chatgpt.com "Keyloop - Automotive Retail Technology for Dealers and OEMs"))

## `KEYKIT`

기존 키보드 앱뿐 아니라 오랫동안 사용된 MIDI 작곡 시스템과 현재 운영되는 API 평가 서비스까지 존재합니다. ([App Store](https://apps.apple.com/us/app/keykit-latin/id914110946?l=ar&utm_source=chatgpt.com "تطبيق KeyKit Latin - App Store"))

# 제 추천

한국에서 먼저 초등학생 대상 MVP를 시작한다면:

> ## **키크 플레이**
>
> ### **KEYK PLAY**
>
> **누르면 살아나는 15초 창작 놀이터**

앱 내부에서는 짧게 그냥 **키크**라고 부릅니다.

- `키크 만들기`
- `내 키크`
- `친구의 키크 눌러보기`
- `키크에 비밀 숨기기`
- `15초 키크 공연`
- `이 키크 리믹스하기`

이렇게 하면 `키크`가 단순 서비스 이름을 넘어 **아이들이 만든 작품 자체를 뜻하는 새로운 단어**가 됩니다.

예를 들어:

> “나 오늘 키크 하나 만들었어.”  
> “이 키크에는 비밀이 두 개 있어.”  
> “네 키크 리믹스해도 돼?”

이 언어가 자연스럽게 형성된다면 브랜드가 매우 강해집니다.
